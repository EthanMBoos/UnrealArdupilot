# Version 1 boundary

Version 1 is one useful, air-started fixed-wing simulation:

```text
Cesium LLA <-> local NED state -> shared Aerosonde model -> Chaos
                                      ^                  |
                                      |                  v
                                  ArduPlane <------ JSON backend
```

It is intentionally smaller than the eventual research platform. The aim is a solid local run that
can be inspected headlessly and extended without first maintaining a release-engineering system.

## Working now

- UE 5.8.1 compiles and opens the project on macOS with Xcode.
- Cesium supplies live longitude, latitude, and ellipsoid height. A local `.env` token enables ion
  terrain; the ellipsoid path works without one.
- The actor starts 500 m above the configured origin at the saved trim state. A chase camera makes
  the flight visible and the normal Unreal window remains interactive.
- The Unreal plugin converts Cesium coordinates to local NED/FRD, calls the shared C++ Aerosonde
  force model, applies its force and moment through Chaos, and sends the committed state to
  ArduPlane's JSON backend.
- The Docker helper waits for GPS/EKF readiness, selects FBWA, arms, and releases the stable PWM
  controls into the simulation.
- `run.py` builds what is needed, launches both processes, and cleans them up together.
- `uvd evaluate`, `simulate`, `trim`, and `linearize` use the same aircraft equations without
  starting Unreal. The headless motion solver is RK4.
- The timestep-refinement script passes locally, and the optional JSBSim fixture agrees with the
  aerodynamic coefficients and loads over its sampled envelope.

These are working-software statements, not a claim that the public educational Aerosonde model is
calibrated to a particular physical airframe.

## What v1 deliberately does not promise

- takeoff, landing, terrain collision, or ground handling;
- sensor error models, actuator dynamics, turbulence, failures, HIL, or flight-data calibration;
- PX4, multiple aircraft types, marine dynamics, or global moving physics frames;
- deterministic replay, evidence bundles, schema infrastructure, or a cross-platform release gate;
- identical Chaos and RK4 trajectories. They are different motion solvers sharing one force model.

The old design documents retain the larger research direction. Add these capabilities when an
experiment needs them, preferably as small modules around the shared core rather than by expanding
the launcher into a general orchestration framework.

## Practical smoke check

Build and exercise the headless side:

```sh
cmake -S . -B build
cmake --build build
build/uvd evaluate examples/run.json
build/uvd simulate examples/run.json --duration 2
build/uvd trim examples/run.json
build/uvd linearize examples/run.json
python3 validation/timestep_convergence.py
```

If the optional JSBSim package is installed:

```sh
python3 validation/jsbsim_compare.py --samples 50
```

Then run the actual v1:

```sh
./run.py
```

A successful run shows the aircraft in the Unreal window, logs Cesium LLA/local NED periodically,
reaches ArduPlane FBWA readiness, arms, and begins applying controller PWM rather than trim commands.
